## 零、入门铺垫 —— 理解Redis的基础概念

### 0.1 什么是Redis？

**一句话定义**：Redis是一个「**存放在内存中的数据库**」。

我们来拆解这句话：
1. **数据库**：意味着它可以存储数据，像MySQL、Oracle一样
2. **内存中**：数据是存放在RAM（随机存取存储器）里，而不是硬盘

**答案：因为内存比硬盘快太多了！**

速度对比：
- 机械硬盘读取一个数据大概需要 **10毫秒**
- 固态硬盘大概是 **0.1毫秒**
- 内存读���只需要 **0.001毫秒**（甚至更快）

也就是说，内存比机械硬盘快 **10000倍**！比固态硬盘快 **100倍**！

### 0.2 Redis可以做什么？

**1. 缓存（Cache）**
```
传统方式：用户请求 → 查数据库 → 返回数据
Redis方式：用户请求 → 查Redis → 直接返回（如果缓存里有的话）
          ↓ （如果没有）
          查数据库 → 写入Redis → 返回数据
```

**2. 分布式锁**
 imagines一个购票系统，有很多台服务器同时服务。如果不加锁，可能会卖出同一张票！Redis可以帮助解决这个问题。

**3. 实时排行榜**
 游戏里谁的分数最高？谁的装备最好？Sorted Set可以轻松实现。

**4. 消息队列**
 可以用于异步处理任务，比如下单后发短信、发邮件等。

**5. 计数器和限流**
 网站的访问量统计、接口限流等。

### 0.3 为什么Redis那么快？

**核心原因1：数据在内存里**
 最关键的原因是数据就在RAM里，不需要去读写硬盘。

**核心原因2：单线程 + IO多路复用**
 - 单线程避免了「线程切换」的开销
 - IO多路复用：Epoll让Redis可以用一个线程同时监视成千上万个连接

**核心原因3：高效的数据结构**
 Redis为每种数据类型都设计了专门的「底层实现」。

**核心原因4：预分配 + 懒删除**
 Redis会预先分配一些内存空间，当要删除数据时，不是立刻回收空间。

## 第一章 基础概念篇（高频 ★★★★★）

### 1. 什么是Redis？为什么要用Redis？

> Redis（全称：Remote Dictionary Server，远程字典服务器）是一个**开源的、基于内存的、K-V键值对存储系统**。它可以用作**数据库、缓存和消息队列**。

**为什么要用Redis？（背也要背下来）**

**角度1：高性能**
 - MySQL查询：约 1,000-10,000次/秒
 - Redis查询：约 100,000+ 次/秒
 - 差距：10-100倍！

**角度2：丰富的数据结构**
 - String（字符串）、Hash（哈希表）
 - List（列表）、Set（集合）
 - Sorted Set（有序集合）
 - Bitmap（位图）、HyperLogLog、GEO（地理位置）

**角度3：单线程 + IO多路复用**
 高并发不再是问题。

**角度4：丰富的特性**
 - 持久化、事务、发布订阅、Lua脚本、Pipeline

---

### 2. Redis为什么这么快？

**原因一：纯内存操作**
 数据在内存里，这是所有快的前提。

**原因二：单线程模型**
 - 避免了锁的开销
 - 没有线程切换开销

**原因三：IO多路复用**
 使用了Linux的epoll技术，一个单线程可以同时监视海量连接。

**原因四：高效的数据结构**
 - String → SDS（简单动态字符串）
 - Hash → 字典 + 渐进式rehash
 - Sorted Set → Skip List（跳表）+ 字典

**原因五：预分配 + 懒删除**
 减少了内存分配的开销。

---

### 3. Redis有哪些数据结构？

| 数据类型 | 底层实现 | 时间复杂度 | 典型场景 |
|---------|---------|-----------|----------|
| String | SDS | O(1) | 缓存、计数器、锁 |
| Hash | ZipList/Dict | O(1)/O(N) | 对象、购物车 |
| List | QuickList | O(1)/O(N) | 队列、列表 |
| Set | IntSet/Dict | O(1)/O(N) | 去重、标签 |
| Sorted Set | SkipList+Dict | O(logN)/O(logN) | 排行榜、延迟队列 |
| BitMap | String | O(1) | 签到、状态 |
| HyperLogLog | 概率结构 | O(1) | UV统计 |
| GEO | GeoHash+SortedSet | O(logN) | LBS |

## 第二章 深入理解底层实现

### 4. String类型的底层实现？

**SDS（Simple Dynamic String）相比C字符串的优势：**

1. **O(1)复杂度获取长度**：SDS有一个len字段，直接读取就行
2. **二进制安全**：SDS用len字段判断，可以存储任何二进制数据
3. **空间预分配**：当字符串增长时，SDS会预分��更多空间
4. **惰性释放**：删除数据时不立即回收空间

```c
struct sdshdr {
    int len;    // 记录已使用的长度
    int free;  // 记录剩余空间
    char buf[];// 实际存放数据
};
```

---

### 5. Hash表是如何实现的？如何解决哈希冲突？

**Redis的解决方案：链地址法**
```
数组：
┌───┬───┬───┬───┬───┬───┐
│ 0 │ 1 │ 2 │ 3 │ 4 │ 5 │
└───┴───┴───┴───┴───┴───┘
              ↓
            ┌───────┐
            │ apple │ → null
            └───────┘
冲突时（新来的banana）：
              ↓
            ┌───────┐      ┌───────┐
            │ apple │ ──→  │banana │ → null
            └───────┘      └───────┘
```

**渐进式rehash**
1. 创建新数组（更大）
2. 把迁移操作分散到每次读写中
3. 迁移期间：两个数组都用
4. 完成后：新数组变主数组

---

### 6. List、Set、Sorted Set的底层实现？

**List：QuickList**
 - 现代版本使用的是QuickList = 「压缩列表+双向链表」的组合

**Set：IntSet + Dict**
 - 当所有元素都是整数时：用IntSet（节省空间）
 - 其他情况：用Dict

**Sorted Set：SkipList + Dict**
 - SkipList保证元素是有序的，查找是O(logN)
 - Dict保证可以通过Key直接找到位置，查询分数是O(1)

## 第三章 持久化机制 —— 数据怎么保存？（中高频 ★★★★）

### 7. Redis有哪些持久化方式？

**RDB（Redis Database）**：定时生成「快照」
 - 某一时刻的所有数据 → 生成一个文件（RDB文件）
 - 恢复时：直接读取这个文件

**AOF（Append Only File）**：记录「写操作命令」
 - 每次执行写操作 → 追加一条记录到文件
 - 恢复时：重新执行所有命令

**混合模式（Redis 4.0+）**
 - AOF文件前半部分是RDB格式，后半部分是AOF格式

---

### 8. RDB和AOF的区别？如何选择？

| 对比项 | RDB | AOF |
|--------|-----|-----|
| 文件体积 | 小（压缩过） | 大（文本） |
| 恢复速度 | 快 | 慢 |
| 数据安全性 | 可能丢数据 | 可配置 |
| 写入方式 | 一次性全量 | 增量追加 |

**场景选择：**
- 用RDB：对数据完整性要求不高，主要追求性能
- 用AOF：对数据完整性要求高，不能接受数据丢失

## 第四章 缓存与性能 —— 如何正确使用Redis作为缓存？（高频 ★★★★★）

### 10. Redis如何作为缓存使用？

**缓存的基本模式（Cache Aside）：**
```
有缓存时：缓存 → 返回
无缓存时：
  1. 查数据库
  2. 写入Redis
  3. 返回
```

---

### 11. 什么是缓存穿透？如何解决？

**缓存穿透**：一个数据，Redis缓存里没有，数据库里也没有。每次请求都穿透到数据库。

**解决方案：**
1. **空值缓存**：第一次穿透时，写入空值到Redis
2. **布隆过滤器**：用一个数组存「可能存在」或「肯定不存在」
3. **前端校验**：参数校验、限流、黑名单

---

### 12. 什么是缓存击穿？如何解决？

**缓存击穿**：一个「热点」key，突然过期了！在过期的瞬间，大量请求同时穿透到数据库。

**解决方案：**
1. **互斥锁**：只有拿到锁的请求去查DB
2. **逻辑过期（永不过期）**：数据放进去就不删
3. **双key**：存两份，有备份

---

### 13. 什么是缓存雪崩？如何解决？

**缓存雪崩**：大量缓存key，同时过期！或者Redis本身挂了！

**解决方案：**
1. **过期时间加随机值**：分散开，不要同时过期
2. **多级缓存**：L1本地缓存 → L2 Redis缓存 → L3数据库
3. **高可用架构**：主从 + Sentinel/Cluster
4. **服务熔限流**：超过阈值 → 排队/拒绝

---

### 14. 如何保证Redis缓存和数据库一致性？

**基本模式：Cache Aside**
```
读：Redis → 有 → 返回
     → 无 → 查DB → 写Redis → 返回

写：DB更新 → 删除Redis（不是更新！）
```

**为什么是「删除」而不是「更新」？**
- 删除方式更安全：并发情况下，下次都会重新加载，最终一致

**强一致性方案：**
1. **延迟双删**：更新DB → 删除Redis → 延迟500ms → 再次删除
2. **订阅binlog**：MySQL → binlog → Canal → Redis更新
3. **分布式锁**：写之前先获取锁

## 第五章 内存管理与淘汰策略 —— 内存不够怎么办？

### 15. Redis有哪些内存淘汰策略？

| 策略 | 说明 |
|-----|------|
| noeviction | 不淘汰，报错（默认）|
| volatile-lru | 只淘汰有TTL的，用LRU算法 |
| allkeys-lru | 所有key都用LRU |
| volatile-lfu | 只淘汰有TTL的，用LFU算法 |
| allkeys-lfu | 所有key都用LFU |
| volatile-random | 随机淘汰有TTL的 |
| allkeys-random | 随机淘汰所有 |
| volatile-ttl | 淘汰TTL最小的 |

**LRU vs LFU：**
- LRU：最近最少使用，适合热点集中的场景
- LFU：最不经常使用，适合热点分散的场景

---

### 16. Redis内存是如何管理的？

**内存分配器：jemalloc**
 - 默认的内存分配器，快、碎片少

**内存碎片：**
- 产生原因：预分配的空间没完全使用、删除数据后留下空洞
- 解决方案：Redis 4.0+有自动碎片清理

## 第六章 事务与Lua脚本

### 18. Redis事务是怎么实现的？

**三个命令：**
```
WATCH key       # 监控一个key，如果变动则事务失败
MULTI          # 开始事务
SET key value  # 加入队列，但不执行
EXEC/ DISCARD # 执行/放弃
```

**特点：**
- ❌ 没有回滚
- △ 没有隔离性
- WATCH只是乐观锁

---

### 20. 什么是Lua脚本？为什么使用Lua？

**为什么要用Lua？**

1. **减少网络往返**：一条Lua脚本可以包含多条命令
2. **原子性**：整个脚本作为原子执行，适合「检查-然后操作」的场景

**实际案例 - 扣库存：**
```lua
local stock = redis.call('GET', KEYS[1])
if tonumber(stock) >= tonumber(ARGV[1]) then
    redis.call('DECRBY', KEYS[1], ARGV[1])
    return 'OK'
else
    return 'NO_STOCK'
end
```

## 第七章 分布式锁

### 21. 如何实现Redis分布式锁？

**基础版：**
```redis
SET lock_key unique_id NX EX 30
# 唯一的值（UUID），30秒过期
# 用完释放
DEL lock_key
```

**进阶版 - 释放锁：**
```lua
-- 释放：只有持有者才能释放
if redis.call('GET', KEYS[1]) == ARGV[1] then
    return redis.call('DEL', KEYS[1])
else
    return 0
end
```

## 第八章 集群与高可用

### 24. Redis有哪些集群模式？

1. **Standalone**：单机，开发/测试用
2. **Master-Slave + Sentinel**：生产常用的高可用方案
3. **Cluster**：数据分片，支持水平扩展

---

### 25. 主从复制原理？

**三种复制方式：**
- **全量复制**：首次复制，传递完整的RDB文件
- **增量复制**：断线重连，复制积压缓冲区的命令
- **无盘复制**：直接通过网络

---

### 26. Sentinel（哨兵）模式？

Sentinel的作用：
1. 监控：检查主从是否健康
2. 故障转移：选出新主，自动切换
3. 通知：告诉客户端新主是谁

---

### 27. Redis Cluster数据是如何分片的？

**槽位分配：**
```
16384个槽位，每个Redis管理一部分
CRC16(数据) % 16384 = 槽位
```

**路由：**
- MOVED重定向：告诉client去正确的node查询
- ASK重定向：迁移过程中的临时跳转
